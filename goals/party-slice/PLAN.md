# Plan

`done`. Schema and vocabulary come first. Each step says what it builds, what it leaves out and how it is checked
before code is written; it ends with `bun run check` passing, `bun run format -- <its files>`, and one conventional
commit; the app is never broken between steps. Nothing is pushed.

group of terms with the marks or the named fixtures that state each of its properties, and gates 1 to 8 pass
together at the end of each. A property no record marks and no question reads enters only on a fixture SPEC's O2
names, and only under O2's recommendation; under its option (d) it stays out.

## Step 1

- Builds: in `@beep/vocabulary`, the nine kind tags with C7 holding tag and identity together (a category has
  none), `categoryParents` with C3's walk following them and a new C14 for their place, a `deprecation` value with a
  new C15 for report 05's V14, gist properties on the gist list with an optional domain and range, a property's
  `subPropertyOf` naming one, rule C9, and `xsd:boolean` in the registry.
- Leaves out: the projector, gates 3 and 5, the lift and the queries (steps 2 to 5); V16, V17's `notApplicable`,
  V18 and the rest of report 05 (O18); any term, gist name or gist property in the kernel's module.
- Checked by: `Rules.test.ts` and `Vocabulary.test.ts`, one planted mistake per new refusal with a near miss that
  passes, each seen to fail with its rule taken out; the kernel's literal decoding with gate 4 silent; `bun run
  ontology:write` then `git diff --exit-code packages/ontology/generated`; `bun run check`.

Choices the SPEC left open, each the agent's:

- **Rule names.** C3 and C7 widen; the new rules are C14 (a category parent is a class tagged `category`, named
  once, and no class's one parent is a category) and C15 (a retirement), after report 14 section 6.4's thirteen.
- **A category's criterion is absent**: `identity` is optional on a class and C7 asks it of every tag but
  `category`, which takes none. C7 states it for kind, relator, event, information and value, and inherits it for
  subkind, phase and role (V17). A role with no local parent is C11's finding alone, and C7 gives one finding a class.
- **A retirement is `replaced` (`replacedBy`, `since`) or `withdrawn` (`reason`, `since`)**, on every term, concepts
  included, so a retirement with no successor cannot leave out its reason. `replacedBy` is a key of the term's own
  table, a concept's a notation of its own scheme, and C15 checks the table; `since` is a version not after the
  vocabulary's. A live class's parent and category parents and a live property's domain and range may not name a
  retired term (V14); a live concept's `alsoInstanceOf` is not checked, since V14 does not list it.
- **A gist property is a relation or an attribute**, keyed by its gist name, with gist's domain (a gist class) and
  range (a gist class, or a datatype) as options; it has no gist parent of its own, which no step needs. A
  property's `subPropertyOf` names a gist property only, `{ kind: "gist", name }`, as `GistParent` does for a class.
- **What C9 calls falling under**: a domain or class range falls under a gist class its class reaches through local,
  category and gist parents; an undeclared domain falls under no declared one; a scheme range falls under no gist
  class (decision 17), so it passes only a gist property that declares no range; a datatype falls under the same
  datatype only.
- **What C9 holds of the gist list itself**: a gist property's declared domain and class range are gist classes on
  the list, found at the gist property's name, as C6 finds a disjoint pair's. A gist property no property sits under
  is not refused, as C5 refuses no gist class that no class reaches; the list's own description ("none unless a
  property sits under one") is kept by hand, unchecked.

Choices the SPEC left open, each the agent's:

- **The history note's words.** A replaced term's is "Deprecated in 0.4.0." (report 05 section 8); a withdrawn term's
  adds its reason after it, so the files say why when nothing replaces it. The note is English text, as the labels are.
- **Where a retirement is written.** A class and a property in the OWL file; a scheme and a concept in the SKOS file,
  keeping its notation, scheme and top-concept link (report 12 section 3); and every retired concept again on its OWL
  individual, since the OWL file makes every concept an individual, not only those with `alsoInstanceOf`.
- **A retired concept loses its class assertion.** It stays an `owl:NamedIndividual`, but its `rdf:type` to the class
  of `alsoInstanceOf` is not written: report 05 section 8 lists parent, disjointness, domain and range, and decision 33
  and SPEC's acceptance say every logical axiom, which in OWL 2 a class assertion is. Keeping it is the other reading;
  it would change one line of the projector and the copy's test.
- **The two annotation properties are declared only when used.** `skos:historyNote` when the OWL file states a
  retirement, of a class, a property or a concept; `dcterms:isReplacedBy` when one of those is replaced. The OWL file
  writes no scheme, so a retired scheme declares neither there. The kernel's files, which retire nothing, keep every
  byte. `owl:deprecated` is OWL's own and is not declared.
- **A gist property's declaration sits among the properties of its kind** (report 12 section 3.1, rule 5), and states
  its type and nothing else: no words of gist's, no domain or range (decision 16).
- **A gist property's own gist parent is not copied yet.** Decision 16's first clause copies "each taken gist
  property's named `rdfs:subPropertyOf`"; step 1 gave a gist property no parent field, since no slice-1 term needs one
  (report 11's `gist:isRecordedAt` under `gist:atDateTime` comes with the commitment slice). So the projector writes
  none and gate 3 refuses one, as two findings, like a domain or a range (a planted test in `Generated.test.ts`); the
  step that brings a term needing one builds the field and moves the link onto gate 3's list. This defers part of an
  answered decision, so step 6 puts it to Benjamin with "Choices made" (What the design left unchecked).
- **The writer writes a boolean as Turtle's bare `true` or `false`** and refuses any other text, XSD's `1` and `0`
  included, so a value has one spelling; it refuses a date-time outside the `xsd:dateTime` lexical space, a day alone
  among them (decision 16's day strings), and a day past its month's end, 29 February outside a leap year included
  (XML Schema 1.1 part 2, section 3.3.7.2). Both refusals are the writer's, beside its NFC check: the graph's literal
  schema stays generic over datatypes.
- **Gate 3's rule for a gist property**: a gist subject typed `owl:ObjectProperty` or `owl:DatatypeProperty` passes only
  when the gist list holds that name with that kind; any other statement about it falls to the class rule and is
  refused, so a gist property's domain or range is two findings (no class on the list, and nothing a gist subject
  carries).
- **The in-memory copy** (`test/support/constructs.ts`) is the kernel's literal with `Party` (decision 12), a retired
  `Workspace` under `Organization` and `Party`, a withdrawn `action`, a retired relation `workspaceMembership` (a
  domain, a class range, under `isCategorizedBy`) and a retired attribute `loggedAt` (under `plantedAttribute`), a
  retired concept and scheme, a retired `MemberRoleScheme-owner` that is also a `Role`, `grantScope` under
  `isCategorizedBy` and a boolean `onHold`, and a copy of the exception list with `Party`'s entry. Each retired term
  holds an axiom its retirement drops, and a test states each one's whole projection. Its gist list is planted: `isCategorizedBy` states no
  domain or range, and `plantedAttribute` is no gist name. None of it is an accepted term.
