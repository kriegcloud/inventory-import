- **Design before code**: Schemas, then the service contract, then the code (`CLAUDE.md` "Adding a feature").
  Check: the plan names the Schemas and endpoints before any component.
- **Challenge me** once, before building, with evidence and a better option, as a type, a schema or a flow; then do
  what I decide. Check: each plan names one risk or alternative.
- **Look before guessing**: read every file the task comes with, and how existing projects solve the same job.
  Check: the write-up says what each choice rests on.
- **Plain first, then reach**: once a plain version works end to end, offer two or three ambitious additions, each
  with what it gains and what it gives up, never a guess in minutes; I pick. Check: the write-up says where it
  reached and what it kept plain.
- **Numbers come from a run**, not an estimate. Check: each number in a report names its command.
- **Contract first, then parallel agents**: commit the Schemas and API contract first; each brief names the files
  its agent owns and the files to read first. Check: `git log --stat` shows no file in two agents' commits.
- **Write it down**: a correction I make twice becomes a rule here or in `CLAUDE.md`. Check: the rule is in one of
  them, in the commit that followed the second correction.
